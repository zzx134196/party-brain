## 一、系统部署

### 1.1 环境要求

| 组件 | 最低要求 | 推荐配置 |
|------|---------|---------|
| Python | 3.11+ | 3.11 |
| Node.js | 18+ | 20 LTS |
| 数据库 | SQLite（开发） | MySQL 8.0（生产） |
| 向量数据库 | 可选 | Milvus 2.3 |
| LLM服务 | 任意OpenAI兼容接口 | Ollama/vLLM/DeepSeek API |

### 1.2 快速部署

**方式一：本地开发**
```bash
# 后端
cd party-brain/backend
cp .env.example .env        # 编辑.env配置数据库和LLM
pip install -r requirements.txt
python3.11 -m uvicorn app.main:app --reload --port 8000

# 前端
cd party-brain/frontend
npm install
npm run dev
```

**方式二：Docker部署**
```bash
cd party-brain
cp backend/.env.example backend/.env
docker-compose up -d
```

### 1.3 默认账号

系统首次启动会自动创建管理员账号：
- 用户名：`admin`
- 密码：`admin123`

> ⚠️ **请在首次登录后立即修改密码**

### 1.4 访问地址

| 服务 | 地址 |
|------|------|
| 前端界面 | http://localhost:3000 |
| 后端API | http://localhost:8000 |
| API文档（Swagger） | http://localhost:8000/docs |
| API文档（ReDoc） | http://localhost:8000/redoc |

## 二、LLM模型配置

### 2.1 进入配置页面

管理后台 → 左侧菜单「LLM配置」

### 2.2 配置项说明

| 配置项 | 说明 | 示例 |
|--------|------|------|
| API地址 | LLM服务的OpenAI兼容接口地址 | `http://localhost:11434/v1` |
| API Key | 认证密钥（本地部署填 `not-needed`） | `sk-xxx` 或 `not-needed` |
| 模型名称 | 模型标识符 | `qwen2.5` / `deepseek-chat` |
| 最大Token数 | 单次生成的最大Token | 4096 |
| 温度 | 生成随机性（0=精确，1=创意） | 0.7 |

### 2.3 常用LLM服务配置

| 服务 | API地址 | API Key | 模型名称 |
|------|--------|---------|---------|
| Ollama（本地） | `http://localhost:11434/v1` | `not-needed` | `qwen2.5` |
| vLLM（本地） | `http://localhost:8080/v1` | `not-needed` | 按部署配置 |
| DeepSeek | `https://api.deepseek.com/v1` | 你的API Key | `deepseek-chat` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | 你的API Key | `qwen-plus` |
| 智谱GLM | `https://open.bigmodel.cn/api/paas/v4` | 你的API Key | `glm-4` |

### 2.4 测试连接

1. 填入配置后，点击「测试连接」按钮
2. 系统会发送一条测试消息验证连通性
3. 显示绿色"连接成功"后，点击「保存配置」

### 2.5 配置持久化

- 配置保存在数据库中（`system_configs`表），重启不丢失
- 启动时自动从数据库加载已保存的配置

### 2.6 Embedding模型配置

用于政策知识库的向量检索。如果不使用Milvus向量检索，可以不配置（系统会自动回退到关键词检索）。

## 三、模板管理

### 3.1 进入模板管理

管理后台 → 左侧菜单「模板管理」

### 3.2 查看模板列表

页面显示所有模板，包含：序号、模板名称、类型、必填字段、状态、更新时间。

### 3.3 新增模板

1. 点击右上角「新增模板」
2. 填写模板信息：

| 字段 | 必填 | 说明 |
|------|------|------|
| 模板名称 | 是 | 如"年度工作计划" |
| 类型 | 是 | 计划/方案/总结/报告/记录 |
| 描述 | 否 | 模板用途说明 |
| 必填字段 | 否 | 用顿号分隔，如"年度、部门名称、工作目标" |
| 选填字段 | 否 | 用顿号分隔，如"特殊要求" |
| 模板骨架 | 否 | 文档结构骨架（章节标题），AI会按此结构生成内容 |

3. 点击「保存」

### 3.4 编辑/删除模板

- 点击模板行的「编辑」按钮修改模板
- 点击「删除」按钮删除模板（不可恢复）

### 3.5 模板骨架编写规范

模板骨架定义了AI生成文档的结构，示例：

```
一、总体思路
二、工作目标
三、重点任务
  （一）任务一
  （二）任务二
  （三）任务三
四、时间安排
  第一季度：
  第二季度：
  第三季度：
  第四季度：
五、保障措施
六、组织领导
```

AI会按照这个骨架填充具体内容。骨架越详细，生成的文档结构越好。

## 四、党员数据管理

### 4.1 导入党员数据

**通过API导入**：
1. 准备Excel或CSV文件
2. 调用 `POST /api/members/import` 上传文件

**Excel字段映射**：

系统自动识别以下列名（支持中文列名）：

| Excel列名 | 数据库字段 |
|-----------|-----------|
| 姓名 | name |
| 性别 | gender |
| 出生日期 | birth_date |
| 部门 / 支部 / 所属支部 | department |
| 职务 | position |
| 学历 | education |
| 电话 / 联系电话 | phone |
| 入党日期 | join_party_date |
| 转正日期 | become_full_date |
| 状态 | status（正式/预备/转出） |
| 民族 | ethnicity |
| 备注 | remark |

### 4.2 查看党员数据

通过API查看：`GET /api/members/?page=1&page_size=20`

支持筛选参数：
- `department`：按支部筛选
- `status`：按状态筛选（正式/预备/转出）
- `keyword`：按姓名模糊搜索

### 4.3 统计接口

| 接口 | 说明 |
|------|------|
| `GET /api/members/stats/departments` | 各支部党员人数统计 |
| `GET /api/members/stats/age` | 年龄段分布统计 |

## 五、政策知识库管理

### 5.1 进入知识库管理

管理后台 → 左侧菜单「知识库管理」

### 5.2 上传政策文件

1. 点击右上角「上传文件」
2. 选择PDF或Word文件
3. 文件上传后状态显示为「等待处理」

### 5.3 解析入库

1. 点击文件行的「解析入库」按钮
2. 系统自动执行：文档解析 → 按条款切片 → 存储到数据库
3. 处理完成后状态变为「已入库」，并显示切片条款数

### 5.4 查看切片

点击「查看条款」可以查看该文档被切分为多少个条款，以及每个条款的内容。

### 5.5 废止/删除

- **废止**：标记文件为「废止」状态，不再参与检索，但保留记录
- **删除**：彻底删除文件及其切片数据

### 5.6 检索机制

系统支持两种检索模式，自动选择：

| 模式 | 条件 | 说明 |
|------|------|------|
| Milvus向量检索 | Milvus服务可用 + Embedding模型已配置 | 语义理解更精准 |
| SQLite关键词检索 | Milvus不可用时自动回退 | 基于关键词匹配，无需额外部署 |

### 5.7 知识库概览

页面顶部显示三个统计卡片：
- 文件总数
- 已入库文件数
- 已入库条款总数

## 六、文件差异对比

### 6.1 进入文件对比

管理后台 → 左侧菜单「文件对比」

### 6.2 操作步骤

1. 在「文件1（旧版）」区域上传第一份文件
2. 在「文件2（新版）」区域上传第二份文件
3. 点击「开始对比」
4. 等待分析完成，查看差异报告

### 6.3 支持格式

- PDF (.pdf)
- Word (.docx, .doc)
- 纯文本 (.txt)

### 6.4 差异报告内容

- 差异数量和相似度百分比
- 差异分类标签：修改/新增/删除
- 每处差异的旧版内容和新版内容
- LLM智能分析的变更说明（需LLM模型已连接）

## 九、系统维护

### 9.1 数据备份

**SQLite模式**：
```bash
cp party-brain/backend/party_brain.db party_brain_backup_$(date +%Y%m%d).db
```

**MySQL模式**：
```bash
mysqldump -u root -p party_brain > backup_$(date +%Y%m%d).sql
```

### 9.2 日志查看

后端运行日志直接输出到控制台。生产环境建议配置日志文件：
```bash
python3.11 -m uvicorn app.main:app --port 8000 2>&1 | tee -a logs/app.log
```

### 9.3 重启服务

```bash
# 停止
lsof -ti:8000 | xargs kill -9

# 启动
cd party-brain/backend
python3.11 -m uvicorn app.main:app --port 8000
```

### 9.4 数据库迁移

如需从SQLite迁移到MySQL：
1. 修改 `.env` 中的 `DATABASE_URL`
2. 重启后端，系统自动创建MySQL表
3. 手动迁移数据（导出CSV → 重新导入）

## 十一、常见故障排查

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| 启动报"Address already in use" | 端口被占用 | `lsof -ti:8000 \| xargs kill -9` |
| 登录失败 | 密码错误或账号不存在 | 默认admin/admin123 |
| LLM调用超时 | 模型服务响应慢 | 检查LLM服务状态，增加超时时间 |
| "DetachedInstanceError" | SQLAlchemy会话问题 | 重启后端 |
| 知识库检索无结果 | 未上传/解析政策文件 | 管理后台上传并点击"解析入库" |
| 前端白屏 | 前端构建失败 | `cd frontend && npm install && npm run dev` |
| Excel导入失败 | 列名不匹配 | 参考4.1节字段映射表调整Excel列名 |
| Docker启动失败 | 端口冲突或镜像拉取失败 | 检查端口占用，配置Docker镜像加速 |

## 十二、安全注意事项

1. **修改默认密码**：首次部署后立即修改admin密码
2. **LLM私有化**：涉及党员个人信息，建议使用本地部署的LLM，避免数据外传
3. **网络隔离**：生产环境建议部署在内网，不暴露到公网
4. **定期备份**：建议每周备份数据库
5. **CORS限制**：生产环境将 `allow_origins=["*"]` 修改为具体域名
6. **HTTPS**：生产环境配置Nginx反向代理+SSL证书
